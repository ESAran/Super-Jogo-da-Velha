# IDEIA-005 — Plataforma web e possível evolução futura

- **Registrada em:** 15/10/2026, recuperando discussões anteriores.
- **Atualizada em:** 15/10/2026.
- **Origem:** dúvidas e possibilidades levantadas pelo usuário.
- **Situação:** Em avaliação futura; sem migração aprovada.

## O que motivou a discussão

O usuário questionou se uma API em Python era o melhor caminho para desenvolver o jogo e comparou uma implementação web com uma engine como Unity. Queria entender como um jogo em HTML/CSS/TypeScript roda, se pode executar localmente e até onde pode chegar em visual, som e animação.

Transformice foi citado como uma referência para entender o formato de um jogo acessado pelo navegador. Essa comparação não equivale a uma decisão de copiar suas mecânicas ou adicionar multiplayer online ao projeto.

## Caminho que já foi adotado

A primeira versão foi migrada para web, sem API Python para jogar, e publicada para compartilhamento. O protótipo anterior permanece no histórico do Git. Isso é contexto de uma decisão executada, não uma tarefa pendente desta caixinha.

## Possibilidade que continua guardada

O usuário considerou começar com HTML e, se a experiência não chegasse ao resultado desejado, mudar depois de tecnologia ou linguagem. Uma engine foi uma alternativa mencionada, não uma próxima etapa já autorizada.

Essa possibilidade fica registrada para reconsideração se surgir uma limitação concreta. Não existe definição de engine de destino, prazo, orçamento ou escopo de migração.

## Observações para avaliar depois

Estas são considerações do assistente, não compromissos do usuário:

- Diferenciar uma limitação da plataforma de uma funcionalidade que ainda não foi implementada.
- Testar visual, áudio, animações e desempenho no navegador antes de concluir que é necessário trocar de tecnologia.
- Não presumir que migrar de engine ou linguagem será uma transcrição automática: parte da interface, recursos e integração pode precisar ser refeita.
- Preservar a separação entre regras e apresentação ajuda futuras mudanças, mas não elimina todo o trabalho de migração.

## Ainda falta decidir, se essa discussão voltar

- Qual requisito a versão web não conseguiria atender satisfatoriamente?
- O objetivo seria distribuição instalável, outra apresentação ou uma mudança de mecânica?
- O que pode ser reaproveitado e o que precisaria ser refeito?
- O ganho justificaria interromper ou desacelerar o desenvolvimento atual?
